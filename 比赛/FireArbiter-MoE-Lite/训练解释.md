这个训练脚本采用的是**多任务、分阶段联合训练**。模型不是只用一个火焰二分类损失，而是同时监督：

1. 最终火焰分类；
2. 全局、局部和语义三个分支；
3. 四张注意力图；
4. 多专家选择、路由和置信度；
5. 最终概率校准。

总损失可以概括为：

[
\boxed{
L_{\text{total}}
================

\lambda_{\text{cls}}L_{\text{cls}}
+\lambda_{\text{branch}}L_{\text{branch}}
+\lambda_{\text{map}}L_{\text{map}}
+\lambda_{\text{expert}}L_{\text{expert}}
+\lambda_{\text{cal}}L_{\text{cal}}
}
]

这些 (\lambda) 在不同训练阶段会变化。

---

# 一、训练数据包含什么

每个训练样本除了图像，还包含：

```python
{
    "image": ...,                 # 输入图像
    "label": ...,                 # 图片级火焰标签，0/1
    "expert_index": ...,          # 数据所属专家编号
    "expert_valid": ...,          # 专家标签是否有效
    "sample_weight": ...,         # 样本权重
    "attention_pos_mask": ...,    # 火焰正区域Mask
    "attention_neg_mask": ...,    # 明确负区域Mask
    "attention_pos_valid": ...,
    "attention_neg_valid": ...,
}
```

图片级 `label` 始终负责分类监督，正负 Mask 只负责注意力图监督。负样本即使缓存中错误带有正向 Mask，训练时也会忽略正向 Mask。

不同大小的图片在一个 batch 内会被补齐到最大的高宽，并补齐到 32 的整数倍，同时产生：

[
\text{image_valid_mask}\in\mathbb{R}^{B\times1\times H\times W}
]

用于排除填充区域。

# 二、最终分类损失 (L_{\text{cls}})

最终分类使用 `LiteArbiter` 输出的：

```python
output["logit"]  # (B, 1)
```

与图片标签：

```python
label  # (B,)
```

计算带样本权重的二元交叉熵：

[
L_{\text{cls}}
==============

\frac{
\sum_{i=1}^{B}
w_i,
\operatorname{BCEWithLogits}(z_i,y_i)
}{
\sum_{i=1}^{B}w_i
}
]

其中：

* (z_i)：最终分类 Logit；
* (y_i\in{0,1})：火焰标签；
* (w_i)：CSV 中的 `sample_weight`。

代码为：

```python
def weighted_bce(logit, label, sample_weight):
    raw = F.binary_cross_entropy_with_logits(
        logit.view(-1),
        label.view(-1),
        reduction="none",
    )
    return (
        raw * sample_weight.view(-1)
    ).sum() / sample_weight.sum().clamp_min(1e-6)
```

因此：

[
\boxed{
L_{\text{cls}}
==============

\operatorname{WeightedBCE}
(\text{final_logit},y)
}
]

---

# 三、分支辅助损失 (L_{\text{branch}})

模型同时监督三个分支：

* GlobalBranch；
* LocalBranch；
* OWLSemanticEncoder 语义分支。

对应：

```python
output["global_logit"]    # (B, 1)
output["local_logit"]     # (B, 1)
output["semantic_logit"]  # (B, 1)
```

计算公式：

[
\boxed{
L_{\text{branch}}
=================

0.35L_{\text{global}}
+
0.45L_{\text{local}}
+
0.20L_{\text{semantic}}
}
]

其中每一项都是带样本权重的 BCE：

```python
branch = (
    0.35 * weighted_bce(
        output["global_logit"], label, sample_weight
    )
    + 0.45 * weighted_bce(
        output["local_logit"], label, sample_weight
    )
    + 0.20 * weighted_bce(
        output["semantic_logit"], label, sample_weight
    )
)
```

局部分支权重最高，是因为该模型更强调火焰局部区域、上下文区域和显著响应特征。

# 四、注意力图损失 (L_{\text{map}})

训练同时监督四张注意力图：

```python
attention_global
attention_local
attention_semantic
attention_mix
```

总注意力损失：

[
\boxed{
L_{\text{map}}
==============

0.20L_{\text{global-map}}
+
0.65L_{\text{local-map}}
+
0.75L_{\text{semantic-map}}
+
1.00L_{\text{mix-map}}
}
]

其中语义图的负区域惩罚权重为 `0.45`，其他图为 `1.0`。

## 4.1 宽容式正区域监督

该代码没有要求注意力图与人工 Mask 像素级完全相同，而是采用“宽容覆盖”方式。

首先将正向 Mask 扩张：

[
M_{\text{allow}}
================

\operatorname{Dilate}(M_{\text{pos}})
]

扩张核大约为图像最大边长的 12%，用于允许注意力在真实火焰边界附近有一定偏移。

然后计算四项指标。

### 正区域平均响应

[
m_{\text{inside}}
=================

\frac{
\sum A M_{\text{pos}}
}{
\sum M_{\text{pos}}
}
]

希望：

[
m_{\text{inside}}\geq0.40
]

惩罚为：

[
\operatorname{ReLU}(0.40-m_{\text{inside}})^2
]

### 正区域峰值

[
p_{\text{inside}}
=================

\max(A M_{\text{pos}})
]

希望：

[
p_{\text{inside}}\geq0.70
]

惩罚为：

[
0.35,
\operatorname{ReLU}(0.70-p_{\text{inside}})^2
]

### 软覆盖率

代码把注意力阈值 (0.5) 进行平滑处理：

[
C_{\text{soft}}
===============

\frac{
\sum
\sigma(12(A-0.5))M_{\text{pos}}
}{
\sum M_{\text{pos}}
}
]

希望至少覆盖 20% 的目标区域：

[
0.40,
\operatorname{ReLU}(0.20-C_{\text{soft}})^2
]

### 远处泄漏

正向 Mask 经过扩张以后，扩张区以外的区域被视为“远离火焰”的区域：

[
L_{\text{far}}
==============

\frac{
\sum A M_{\text{outside}}
}{
\sum M_{\text{outside}}
}
]

惩罚系数为 `0.25`。

因此正区域损失为：

[
\boxed{
\begin{aligned}
L_{\text{pos-map}}
={}&
\operatorname{ReLU}(0.40-m_{\text{inside}})^2\
&+0.35\operatorname{ReLU}(0.70-p_{\text{inside}})^2\
&+0.40\operatorname{ReLU}(0.20-C_{\text{soft}})^2\
&+0.25L_{\text{far}}
\end{aligned}
}
]

## 4.2 负区域损失

对于明确标为干扰物的负向区域，直接惩罚其中的平均注意力：

[
L_{\text{neg-map}}
==================

\frac{
\sum A M_{\text{neg}}
}{
\sum M_{\text{neg}}
}
]

最终单张图的损失：

[
\boxed{
L_{\text{tolerant-map}}
=======================

L_{\text{pos-map}}
+
\lambda_{\text{neg}}L_{\text{neg-map}}
}
]

若某个样本没有有效 Mask，则对应 Mask 损失为零，不强行进行伪监督。

# 五、专家损失 (L_{\text{expert}})

专家损失由六部分组成：

[
\boxed{
\begin{aligned}
L_{\text{expert}}
={}&L_{\text{selected}}
+0.5L_{\text{routed}}\
&+0.5L_{\text{posterior-KL}}
+0.25L_{\text{confidence}}\
&+0.15L_{\text{prior-guidance}}
+0.02L_{\text{balance}}
\end{aligned}
}
]



---

## 5.1 每个专家自身分类误差

假设专家数量为 (E)，专家输出：

[
Z_{\text{expert}}\in\mathbb{R}^{B\times E}
]

将每张图的标签扩展到所有专家：

[
Y_{\text{expert}}\in\mathbb{R}^{B\times E}
]

计算每个专家的 BCE：

[
e_{i,j}
=======

\operatorname{BCEWithLogits}
(z_{i,j},y_i)
]

得到：

[
E_{\text{error}}\in\mathbb{R}^{B\times E}
]

---

## 5.2 后验路由目标

误差越小的专家，应获得越高的后验权重。

代码构造软目标：

[
q_{i,j}
=======

\operatorname{Softmax}*j
\left(
-\frac{e*{i,j}}{0.5}
\right)
]

这里 `0.5` 是温度，目标误差执行了 `detach()`，因此不会通过该目标反向修改专家 Logit。

再让后验路由权重 (p^{post}) 逼近该目标：

[
\boxed{
L_{\text{posterior-KL}}
=======================

D_{\mathrm{KL}}
(q\Vert p^{post})
}
]

直观含义是：

> 哪个专家对当前图片预测得更准，后验路由就应当给哪个专家更大的权重。

---

## 5.3 专家置信度损失

专家置信度的目标定义为：

[
c^*_{i,j}
=========

e^{-e_{i,j}}
]

专家误差越小：

[
e_{i,j}\downarrow
\quad\Longrightarrow\quad
c^*_{i,j}\uparrow
]

预测置信度与该目标之间使用 Smooth L1：

[
\boxed{
L_{\text{confidence}}
=====================

\operatorname{SmoothL1}
(c_{i,j},e^{-e_{i,j}})
}
]

---

## 5.4 后验路由分类损失

后验路由后的综合专家分数：

```python
posterior_routed_logit  # (B,1)
```

同样与图片标签计算带权 BCE：

[
\boxed{
L_{\text{routed}}
=================

\operatorname{WeightedBCE}
(z_{\text{posterior-route}},y)
}
]

这样可以直接要求后验专家组合给出正确的火焰判断。

---

## 5.5 指定专家监督

如果训练样本带有有效的 `expert_index`，则监督对应专家：

[
L_{\text{selected}}
===================

\operatorname{BCEWithLogits}
(z_{i,e_i},y_i)
]

其中 (e_i) 是样本指定的专家编号。

同时要求先验路由器把较高权重分给该专家：

[
\boxed{
L_{\text{prior-guidance}}
=========================

-\log p^{prior}_{i,e_i}
}
]

这相当于专家类别的交叉熵监督。

---

## 5.6 专家负载均衡

首先计算一个 batch 内所有样本的平均后验权重：

[
\bar p_j
========

\frac{1}{B}
\sum_i p^{post}_{i,j}
]

再与均匀分布：

[
u_j=\frac{1}{E}
]

计算 KL 项。按照当前 `F.kl_div(mean_weight.log(), uniform)` 的参数顺序，实际对应：

[
\boxed{
L_{\text{balance}}
==================

D_{\mathrm{KL}}
(U\Vert\bar P)
}
]

其目的是防止所有样本都长期集中到一个专家上。

需要注意：这是一个较弱的正则项，系数只有 `0.02`。

# 六、校准损失 (L_{\text{cal}})

最终概率：

[
p=\sigma(z)
]

校准损失为均方误差：

[
\boxed{
L_{\text{cal}}
==============

\frac{1}{B}
\sum_i(p_i-y_i)^2
}
]

也就是 Brier Score 形式：

```python
calibration = (
    torch.sigmoid(output["logit"].view(-1)) - label
).pow(2).mean()
```

它不只关心分类对错，还要求：

* 真正火灾样本的概率接近 1；
* 非火灾样本的概率接近 0；
* 避免错误情况下仍然极端自信。

# 八、每个 batch 如何更新参数

训练批次的执行顺序为：

```text
读取并补齐图像
        ↓
根据阶段决定是否强制专家
        ↓
模型前向传播
        ↓
计算五类损失
        ↓
加权得到 total loss
        ↓
混合精度反向传播
        ↓
梯度裁剪
        ↓
AdamW 更新
```

代码使用 CUDA 自动混合精度：

```python
with torch.autocast(..., dtype=torch.float16):
    output = model(...)
    losses = compute_losses(...)
```

然后：

```python
scaler.scale(losses["total"]).backward()
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
scaler.step(optimizer)
scaler.update()
```

所以：

* 使用 FP16 降低显存和加速；
* 使用 `GradScaler` 防止 FP16 梯度下溢；
* 梯度范数限制为 `1.0`，避免训练不稳定。

# 九、优化器和学习率

使用：

[
\boxed{\text{AdamW}}
]

权重衰减：

[
\boxed{10^{-4}}
]

参数根据名称分为三组：

```text
head      除ConvNeXt和OWL原模型以外的模块
backbone  ConvNeXt参数
owl       OWL-ViT原模型参数
```

每组使用不同学习率。若某组学习率为 0，则不会加入优化器。

每一个训练阶段都会重新创建：

```python
CosineAnnealingLR(
    optimizer,
    T_max=stage_total_epochs,
)
```

也就是说，每个阶段都有独立的余弦退火周期，而不是 21 个 epoch 共用一个调度周期。每轮训练结束后执行一次 `scheduler.step()`。

# 十、验证与模型保存

每个 epoch 后都会在验证集上执行完整验证，但不反向传播，然后记录：

* Accuracy；
* Precision；
* Recall；
* Specificity；
* F1；
* Balanced Accuracy；
* AUC；
* ECE；
* Brier Score；
* 注意力图内部覆盖率和远处泄漏；
* 各专家准确率、权重和置信度。

最佳模型不是单纯根据验证 Loss 选择，而是使用：

[
\boxed{
\begin{aligned}
Score={}&
0.45,BalancedAcc
+0.30,F1\
&+0.15,AUC
-0.05,ECE
-0.05,MixFarLeak
\end{aligned}
}
]

即同时考虑：

* 正负样本平衡准确率；
* F1；
* 排序能力；
* 概率校准；
* 注意力图错误泄漏。



每轮会保存：

```text
latest.pth     最新模型
best.pth       综合评分最高模型
best_f1.pth    验证F1最高模型
```

并同步保存纯推理版本、训练历史、专家诊断和注意力可视化。

# 十一、当前代码中一个值得注意的点

验证代码会在：

[
0.05,0.055,\ldots,0.95
]

共 181 个阈值中寻找验证集 F1 最佳阈值，并记录为 `best_threshold`。

但是当前训练脚本中，`set_threshold()` 只在读取 checkpoint 时调用，没有在每轮验证后把 `best_threshold` 写回模型。也就是说：

* 验证日志会显示最佳阈值；
* 保存元数据中会记录最佳阈值；
* 模型内部实际推理阈值通常仍为初始化值 `0.5`。

若预期部署时自动使用验证最佳阈值，需要在确定最佳 checkpoint 时显式执行：

```python
core.set_threshold(
    val_metrics["best_threshold"]
)
```

但应该谨慎决定是在每轮都更新，还是只对最终选中的最佳模型更新，避免验证过程中的阈值变化影响跨 epoch 指标可比性。


下面假设：

```text
专家数量 E = 3
图片真实类别 y = 1（有火焰）
该图片指定给“专家1”
专家1对应代码中的 expert_index = 0
sample_weight = 1
```

先按**未强制路由**的普通情况计算，这样可以清楚看到专家损失每一项的作用。代码中的专家损失由指定专家分类、后验路由分类、后验路由 KL、专家置信度、先验专家引导和负载均衡六部分构成。

# 一、假设模型刚开始随机预测

假设一次前向传播产生以下随机结果：

| 项目                 | 专家1（指定专家） |    专家2 |    专家3 |
| ------------------ | --------: | -----: | -----: |
| 专家 Logit (z_e)     |     -0.20 |   0.30 |  -0.70 |
| 火焰概率 (\sigma(z_e)) |    0.4502 | 0.5744 | 0.3318 |
| 先验路由权重 (p^{prior}) |      0.40 |   0.35 |   0.25 |
| 后验路由权重 (p^{post})  |      0.30 |   0.50 |   0.20 |
| 专家预测置信度            |      0.45 |   0.55 |   0.35 |
| 是否是数据指定专家          |         是 |      否 |      否 |

虽然图片理论上属于专家1，但因为模型刚随机初始化，专家2当前恰好给出了更高的火焰概率。这是允许发生的，后面的不同损失会分别处理“指定专家”和“当前预测更好的专家”。

---

# 二、计算每个专家的分类误差

标签为：

[
y=1
]

每个专家的 BCE 为：

[
e_j=\operatorname{BCEWithLogits}(z_j,1)
=-\log \sigma(z_j)
]

计算结果：

| 专家  | Logit |   火焰概率 | 专家 BCE 误差 |
| --- | ----: | -----: | --------: |
| 专家1 | -0.20 | 0.4502 |    0.7981 |
| 专家2 |  0.30 | 0.5744 |    0.5544 |
| 专家3 | -0.70 | 0.3318 |    1.1032 |

当前随机状态下：

[
e_2<e_1<e_3
]

也就是说，**专家2当前预测最好，但数据指定专家仍然是专家1**。

这两个信息会进入不同监督项：

* `selected_loss` 强制训练专家1；
* `router_target` 根据实际误差，目前更偏向专家2。

---

# 三、指定专家损失 `selected_loss`

代码取出数据指定专家的 Logit：

```python
selected_logits = expert_logits.gather(...)
selected_loss = BCEWithLogits(selected_logits, label)
```

因为指定的是专家1，所以：

[
\boxed{
L_{\text{selected}}=e_1=0.7981
}
]

它会直接推动专家1的 Logit 增大：

```text
专家1 Logit：-0.20 → 更大的值
专家1火焰概率：0.4502 → 更接近1
```

专家2和专家3不直接参与这一项。

---

# 四、后验路由目标 `router_target`

代码不是直接把后验路由目标设置成专家1，而是根据三个专家当前的预测误差构造软目标：

[
q_j=
\operatorname{Softmax}
\left(
-\frac{e_j}{0.5}
\right)
]

其中温度为：

[
T=0.5
]

代入误差：

[
[e_1,e_2,e_3]
=============

[0.7981,0.5544,1.1032]
]

得到：

| 专家  |   专家误差 | (-e_j/0.5) | 路由软目标 (q_j) |
| --- | -----: | ---------: | ----------: |
| 专家1 | 0.7981 |    -1.5963 |      0.3153 |
| 专家2 | 0.5544 |    -1.1087 |      0.5134 |
| 专家3 | 1.1032 |    -2.2064 |      0.1713 |

因此：

[
\boxed{
q=[0.3153,;0.5134,;0.1713]
}
]

这表示：

> 就当前这一次随机预测而言，后验路由器应该更多参考专家2，因为专家2当前误差最小。

代码对专家误差进行了 `detach()`，因此这个软目标不会反向修改专家 Logit，只用于训练后验路由器。

---

# 五、后验路由 KL 损失

假设当前后验路由权重为：

[
p^{post}=[0.30,;0.50,;0.20]
]

目标为：

[
q=[0.3153,;0.5134,;0.1713]
]

损失为：

[
L_{\text{posterior-KL}}
=======================

\sum_jq_j
\log\frac{q_j}{p^{post}_j}
]

代入得到：

[
\boxed{
L_{\text{posterior-KL}}\approx0.00273
}
]

这个值很小，因为当前后验权重：

[
[0.30,0.50,0.20]
]

已经比较接近目标：

[
[0.3153,0.5134,0.1713]
]

---

# 六、专家置信度损失

置信度目标为：

[
c_j^*=\exp(-e_j)
]

本例中：

| 专家  | BCE 误差 | 置信度目标 (e^{-e_j}) |  预测置信度 |
| --- | -----: | ---------------: | -----: |
| 专家1 | 0.7981 |           0.4502 | 0.4500 |
| 专家2 | 0.5544 |           0.5744 | 0.5500 |
| 专家3 | 1.1032 |           0.3318 | 0.3500 |

这里标签是 1，所以：

[
e^{-e_j}=\sigma(z_j)
]

专家置信度使用 Smooth L1：

[
L_{\text{confidence}}
=====================

\operatorname{SmoothL1}
(c,c^*)
]

得到：

[
\boxed{
L_{\text{confidence}}\approx0.000155
}
]

这个损失会教会每个专家：

> 自己预测得越正确，置信度应该越高；预测得越差，置信度应该越低。

---

# 七、后验路由分类损失

后验路由后的综合专家 Logit 为：

[
z_{\text{routed}}
=================

\sum_jp^{post}_jz_j
]

代入：

[
\begin{aligned}
z_{\text{routed}}
={}&0.30(-0.20)
+0.50(0.30)
+0.20(-0.70)\
={}&-0.06+0.15-0.14\
={}&-0.05
\end{aligned}
]

因此综合火焰概率为：

[
\sigma(-0.05)\approx0.4875
]

对于标签 (y=1)，后验路由分类损失为：

[
L_{\text{routed}}
=================

\operatorname{BCEWithLogits}(-0.05,1)
]

得到：

[
\boxed{
L_{\text{routed}}\approx0.7185
}
]

该项要求：

> 即使每个专家单独表现不同，后验加权后的最终专家结论也必须正确。

---

# 八、先验路由引导损失

因为这张图片的数据标签指定为专家1，所以要求先验路由器给专家1更大的权重。

当前先验权重：

[
p^{prior}=[0.40,0.35,0.25]
]

指定专家为专家1，所以：

[
L_{\text{prior-guidance}}
=========================

-\log p^{prior}_1
]

即：

[
\boxed{
L_{\text{prior-guidance}}
=========================

-\log(0.40)
\approx0.9163
}
]

它会推动：

```text
专家1先验权重：0.40 → 增大
专家2、专家3权重：相对减小
```

这一项和 `router_target` 的含义不同：

| 损失               | 监督依据        | 本例偏向 |
| ---------------- | ----------- | ---- |
| `prior_guidance` | 数据预先指定的专家   | 专家1  |
| `posterior_kl`   | 当前各专家实际预测误差 | 专家2  |

这种设计体现了“先验指定”和“后验表现修正”的互惠结构。

---

# 九、专家负载均衡损失

当前只有一张图片，因此 batch 平均后验权重就是：

[
\bar p=[0.30,0.50,0.20]
]

三个专家的均匀目标为：

[
u=
\left[
\frac13,\frac13,\frac13
\right]
]

代码计算：

[
L_{\text{balance}}
==================

D_{\mathrm{KL}}(U\Vert\bar P)
]

得到：

[
\boxed{
L_{\text{balance}}\approx0.07024
}
]

这一项防止路由器长期把所有图片都交给同一个专家。

它只占 `0.02`，因此只是较弱的正则化，不会强制每张图片平均使用三个专家。

---

# 十、专家总损失

代码中的专家损失为：

[
\begin{aligned}
L_{\text{expert}}
={}&L_{\text{selected}}
+0.5L_{\text{routed}}
+0.5L_{\text{posterior-KL}}\
&+0.25L_{\text{confidence}}
+0.15L_{\text{prior-guidance}}
+0.02L_{\text{balance}}
\end{aligned}
]



代入本例：

| 损失项                    |      原始值 |   系数 | 对总专家损失的贡献 |
| ---------------------- | -------: | ---: | --------: |
| 指定专家分类 `selected_loss` |   0.7981 | 1.00 |    0.7981 |
| 后验路由分类 `routed_loss`   |   0.7185 | 0.50 |    0.3592 |
| 后验路由 KL                |  0.00273 | 0.50 |   0.00136 |
| 专家置信度                  | 0.000155 | 0.25 |  0.000039 |
| 先验专家引导                 |   0.9163 | 0.15 |    0.1374 |
| 专家负载均衡                 |  0.07024 | 0.02 |   0.00140 |

最终：

[
\begin{aligned}
L_{\text{expert}}
={}&0.7981
+0.3592
+0.00136\
&+0.000039
+0.1374
+0.00140\
\approx&\boxed{1.2976}
\end{aligned}
]

# 十一、这一次反向传播会做什么

对于这张“属于专家1”的火焰图片，梯度大致会产生以下作用：

| 模块     | 受到的训练作用                            |
| ------ | ---------------------------------- |
| 专家1分类头 | 提高火焰 Logit，因为指定专家1预测偏低             |
| 专家2分类头 | 通过综合路由等路径继续学习，但不承担 `selected_loss` |
| 先验路由器  | 增大专家1的先验权重                         |
| 后验路由器  | 当前暂时更偏向专家2，因为专家2随机预测得更好            |
| 专家置信度头 | 学习预测各专家当前可靠程度                      |
| 专家均衡机制 | 轻微抑制所有样本集中于单一专家                    |

训练一段时间后，理想状态是：

```text
专家1逐渐学会该类图片
    ↓
专家1的分类误差下降
    ↓
router_target也开始偏向专家1
    ↓
先验指定与后验表现逐渐一致
```

---

# 十二、在 `expert_specialization` 阶段的实际差别

你的训练配置在专家专门化阶段设置了：

```python
force_expert = True
```

训练循环会将该图片的 `expert_index` 传入模型；模型随后把有效样本的先验和后验权重都强制替换为 one-hot。 

对于专家1：

[
p^{prior}=p^{post}=[1,0,0]
]

这时：

```text
指定专家分类损失 = 0.7981
后验路由分类损失 = 0.7981
先验引导损失 = -log(1) = 0
```

但当前损失函数会把零权重截断成 (10^{-7})，继续计算后验 KL 和均衡损失。因此，用上面的随机专家 Logit，近似得到：

| 项目                |     强制专家后的数值 |
| ----------------- | -----------: |
| `selected_loss`   |       0.7981 |
| `routed_loss`     |       0.7981 |
| `posterior_kl`    |      10.0277 |
| `confidence_loss` |     0.000155 |
| `prior_guidance`  |            0 |
| `balance`         |       9.6468 |
| **expert loss**   | **约 6.4040** |

这说明当前代码在强制专家阶段存在一个值得注意的现象：

> 路由已经被强制为专家1，但 `posterior_kl` 仍要求它逼近根据随机预测误差产生的软目标，`balance` 仍要求接近均匀分布，因此会产生较大的惩罚。

更符合“强制专家专门化”目的的做法通常是，在 `force_expert=True` 时关闭或屏蔽：

```python
posterior_kl
balance
```

保留：

```python
selected_loss
routed_loss
confidence_loss
```

否则强制 one-hot 路由和路由 KL/均衡目标之间会相互拉扯。
